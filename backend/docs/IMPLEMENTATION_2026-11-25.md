# StoreMate 통합 구현 현황 · 2026-11-25

## 구현한 흐름

- **입고 묶음**: 같은 바코드라도 유통기한별로 나눠 입고한다. 기존 재고는 첫 변경 시 기존 재고 묶음으로 보존한다. 상품 합계는 묶음 합계와 함께 갱신한다. 지난 유통기한 묶음만 폐기하며 날짜 미확인·미도래 재고는 유지한다. 묶음 수정은 버전 검사, 입고는 요청 키로 중복 반영을 방지한다.
- **재고 화면**: 상품 수정·폐기 패널에서 묶음 수량과 날짜를 확인·정정한다. 0개로 저장하면 해당 묶음만 폐기한다. 전체 재고를 줄일 때는 유통기한이 빠른 묶음부터 차감한다.
- **촬영 인식**: 실제 카메라 촬영 → 서버 OCR → 유효한 날짜 후보 → 사용자가 유통기한 선택 → 입고 확인 흐름을 연결했다. 제조일을 유통기한으로 자동 확정하지 않는다. 사진은 DB에 저장하지 않는다. Google Vision 키가 없으면 직접 입력 안내를 표시한다.
- **급여**: [주휴·야간·휴일 자동 계산 설정](PAYROLL_AUTOMATIC.md)을 추가했다. 확인한 약정·휴게·휴일을 기준으로 주휴, 야간, 휴일, 연장 가산과 실제 무급 휴게 차감, 별도 유급휴일 임금을 계산하고 명세에 반영한다. 수정 전 자동 항목은 취소 이력으로 남긴다. 퇴근 완료 기록의 보존 시급으로 기본급을 계산한다. 주휴·연장·야간·휴일·기타 지급·공제·시급 정정 차액을 별도 항목으로 기록한다. 확인한 시간 × 시급 × 배율 또는 직접 확인 금액을 입력한다. 저장자·시각·사유·계산식을 남기며 취소도 삭제 대신 기록한다. 지난달 이후, 미확정 시급과 진행 중 근무가 없고 관리자가 확인한 경우 명세를 확정할 수 있다. 직원은 자기 명세만 조회한다.
- **중요한 급여 범위**: 수당 적용 대상·휴게시간·세율·공제 적법성의 자동 판정은 구현하지 않았다. 근로계약과 적용 기준을 확인한 값을 입력하면 자동으로 금액을 산출하는 계산·명세 기능이다. 완전 자동 법정 급여 정산으로 사용하면 안 된다. 명세 기본급은 출근한 달 기준이며 원 단위 합계 반올림이다. 확정 후에는 원본 명세를 변경하지 않고 다음 명세에 정정 차액을 남긴다.
- **직전 근무자 인수인계**: 현재 출근 시각 이전에 퇴근한 다른 직원의 실제 근무를 찾아 연결한다. 새 메모는 작성자의 실제 근무와 파트를 기록한다. 기존 메모는 동일 작성자의 실제 근무 구간 안에서만 매칭한다. 파트 기록이 없으면 미기록으로 표시한다. 전체 목록과 직전 근무자 목록을 구분하고 직원 홈 요약도 이 조회를 사용한다.
- **퇴근 누락**: 등록 일정 종료 후 유예 시간이 지났거나, 일정 없이 설정한 시간이 경과하면 관리자에게 확인 알림을 만든다. 기본값은 16시간·유예 60분·자동 마감 꺼짐이다. 자동 마감은 관리자가 켠 경우에만 등록 일정의 종료 시각으로 처리하고 감사 사유를 남긴다. 실제 퇴근 시각을 추정하지 않으며 일정 없는 근무는 자동 마감하지 않는다. 관리자는 미확정 급여에 속한 마감 기록의 퇴근 시각을 정정할 수 있고 변경 전후·사유·처리자를 별도 이력으로 보관한다. 확정 명세가 있는 달의 기록은 잠그고 다음 급여의 정정 차액으로 처리한다.
- **푸시**: 기기 등록·로그인 세션 연동·계정 변경 보호·알림 유형 설정·방해 금지 후 전송·실패 재시도·Expo 티켓/영수증 조회·무효 토큰 비활성화를 구현했다. 앱 내 알림은 푸시 설정과 별도로 남는다. 재고 부족·유통기한 알림은 매장 기준으로 매일 오전 9시 한국 시간에 생성한다.
- **매장 설정**: 알림 기준과 근무 파트를 서버에 저장한다. 관리자 MY에서 변경할 수 있다. 기기에만 있던 설정은 관리자 화면에서 불러와 확인한 뒤 저장한다. 자동으로 다른 기기 설정을 덮어쓰지 않는다.
- **안드로이드 표시**: 입력 글자·선택 버튼·프로필·관리자 홈·근무 기록의 글자 여백과 정렬을 정리했다. 근무 기록의 관성 스크롤을 꺼서 중간 위치에 멈출 수 있게 했으며 불필요한 홈 타이머 갱신을 막았다. 네이티브 로그인 토큰은 OS 보안 저장소에 보관하고 이전 토큰을 한 번 이전한다.

## 외부 연결 없이는 완료할 수 없는 검증

1. Google Cloud 프로젝트의 Vision API 사용 설정과 서버 전용 키. 현재 사진 인식 결과를 실제 서비스에서 확인한 것은 아니다.
2. Expo 프로젝트 ID와 Android FCM 자격 증명. `PUSH_ENABLED=true`와 실제 설치 앱 등록 후 기기 수신 검증이 필요하다. Expo Go에서는 실제 원격 푸시 검증을 할 수 없다.
3. 운영 서버·도메인·HTTPS·운영 DB와 백업. 배포 구성은 제공하지만 외부 서버를 생성하거나 배포하지 않았다.
4. 실제 Android 휴대폰의 카메라·QR·키보드·알림 권한·백그라운드 수신·재실행 검증. iOS도 실제 기기와 Apple 서명 계정 검증이 필요하다.

이 항목들이 연결되기 전에는 **배포 완료 또는 앱 전체 최종 검증 완료**라고 할 수 없다.

## 주요 화면

- 재고/발주 → 상품 수정 또는 폐기 → 입고 묶음별 재고·유통기한
- 바코드 입고 → 상품 선택 → 촬영 인식
- 관리자 MY → 직원 급여 관리 → 직원 선택 → 수당·공제·급여 명세
- 직원 MY → 근무 기록 → 수당·공제·급여 명세
- 관리자 직원 급여 관리 → 퇴근 누락 감지·자동 마감 설정
- 인수인계 목록·관리 → 직전 근무자
- 관리자 MY → 매장 알림 기준·근무 파트 설정
- MY → 알림 설정 → 이 기기 푸시 알림 연결

## 보고서 요구사항 보완 (2026-11-25)

- 출고 수량·사유·입고 묶음 선택, FEFO 자동 선택, 현재 재고·묶음 버전 확인을 추가했다. 실사 조정은 관리자만 가능하다.
- 상품 및 기간별 재고 변동 이력과 처리자·사유·전후 수량을 조회한다. 발주 추천은 목표 재고에서 현재 재고를 뺀 규칙 기반 계산이며, 계획 저장은 실제 주문이나 재고 반영이 아니다.
- 업종별 분류·유통기한 사용·예시 업무를 불러오고 수정한다. 예시 업무 등록은 관리자가 명시적으로 선택할 때만 수행한다.
- 미등록 상품은 카메라 OCR의 인식 문구를 선택해 상품명 입력을 보조한다. 외부 상품 카탈로그를 자동 조회하거나 결과를 자동 확정하지 않는다.
- 인수인계 제목·관련 미완료 업무를 연결한다. 메모 읽음과 실제 업무 완료 승인은 독립적이다. 알림에서 관련 업무로 이동한다.
- 휴게 구간을 공통 근무 기록에 저장하고 실근무시간·기본급·자동 급여에 동일하게 반영한다. 중복 구간·범위 밖 시간·확정 급여 변경을 거부한다.
- 관리자 MY에서 매장 위치·출근 반경을 설정하며 0m는 위치 검사를 사용하지 않는 값이다. 위치가 필요한 경우 직원에게 권한을 요청하고 서버에서 거리·정확도·측정 시각을 확인한다. GPS는 조작 방지나 실내 위치 정확성을 보장하지 않는다.
- 직원 연락처·매장 내 표시 이름, 상품 분류·규격·목표 재고, 오늘 예정 근무자를 관리한다. QR 이미지는 사용자 요청에 따라 사진 보관함으로 저장한다.
- Google·카카오 OAuth 시작·콜백·일회용 결과 조회를 구현했다. 실제 공급자 계정 검증은 별도 설정 후 진행해야 하며 미설정 버튼은 연결 준비 중으로 표시한다.
- 홈 상태 숫자를 누르면 해당 상품 또는 현재 근무자만 조회한다. 근무자 사진 자리는 사람 아이콘으로 통일했다.
- 재고는 카테고리별 선택·검색과 발주 필요/유통기한 임박 상품 모아보기를 제공한다. 알림 종은 서버 알림과 관리자 로컬 재고 알림의 읽음 상태를 확인해 점을 표시한다. 열려 있는 화면에서는 15초마다 확인하고 알림 화면에서 돌아오면 다시 조회한다.

상세 외부 설정: [SOCIAL_LOGIN.md](SOCIAL_LOGIN.md). 새로운 위치·사진 모듈을 쓰는 개발 설치 앱은 다시 빌드해야 한다. Expo Go 실행과 배포용 설치 앱 검증은 구분한다.

## 매장별 카테고리 관리

재고 화면의 ‘카테고리 추가·관리’에서 관리자가 분류를 만들고 이름을 변경하거나 삭제한다. 이름 변경은 해당 매장의 기존 상품에 함께 반영되며 수량은 유지된다. 분류 삭제 시 상품은 미분류로 이동한다. 상품이 없는 분류도 서버에 저장되며 재접속 후 유지된다. 수정 버전 충돌·중복 이름·다른 매장 접근을 거부한다. 화장품(스킨케어·메이크업·클렌징·헤어/바디·소품), 의류점(상의·하의·아우터·신발·액세서리) 템플릿을 추가했다. 새 매장 등록과 MY 템플릿에서 선택 가능하며, 기존 분류는 관리자의 선택 없이 삭제하지 않는다.

## 발주 입고 연계·교대 요약·일괄 실사·직원 권한

- 발주 계획은 발주 전 → 발주 완료 표시 → 일부 입고 → 입고 완료로 이어진다. 발주 완료 표시는 외부 업체 주문 전송이 아니다. 승인된 매장 구성원이 계획별 잔량 안에서 실제 입고를 확인하면 수량·유통기한 묶음·기존 입고 이력을 갱신한다. 입고 요청 키·계획 개정 검사로 중복·동시 입고를 막고 처리자·날짜·입고량·재고 전후를 별도 기록한다.
- 사장님/직원 홈의 교대 요약에서 미완료 업무·본인이 아직 확인하지 않은 긴급 메모·유통기한 확인 상품·직전 근무자 메모를 모아 본다. 긴급 메모 확인과 업무 승인은 독립적이다.
- 여러 상품 실사는 검색·50개씩 조회·빈칸 건너뛰기·0개 입력·차이 미리 보기 후 저장을 제공한다. 한 번에 최대 100개를 처리하고 모든 재고 스냅샷을 먼저 검사한다. 하나라도 충돌하면 전체 변경을 거부한다. 변동이 없는 실사도 확인 기록을 남긴다.
- 사장님은 직원별 상품 삭제·재고 조정·발주 계획 저장/발주 완료 표시 권한을 설정한다. 기본값은 모두 꺼짐이다. 화면과 서버 양쪽에 적용하며 기존 단일 상품 조정·묶음 조정 경로도 검사한다. 일반 입고·출고 권한은 승인된 매장 구성원에게 유지된다.
- iOS 실제 검증 준비: 앱을 다시 실행해도 전경 푸시 표시 처리를 초기화한다. 서버 OCR·푸시 환경 변수도 기존 개인 설정 파일과 함께 읽도록 보완했다. 외부 키와 실제 휴대폰 수신/인식 성공은 아직 검증하지 않았다.
